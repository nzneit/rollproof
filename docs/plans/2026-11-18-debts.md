# rollproof: the debts of the install-window plan — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clear what the install-window plan left: the false `internal-error` at the end of a run, the one deadline for all of the cluster's creation, the probe's record after a signal, the order of the stop after a failure of the tool, the exit by a signal, and the parked robustness, tests, polish and names.

**Architecture:** No unit is added. `probe` learns that, after the stop, a stream that ends while the container is ending is the end of the log, and gives its line counts at any moment. `run` stops commands before the probe after a failure of the tool and records how the probe's stop went. `report` writes `stopped_when_asked` as null when the tool did not ask or did not finish. `cmd/rollproof` ends by the signal that stopped the run. `cluster` gives each wait its own limit.

**Tech Stack:** As built: Go 1.27, `k8s.io/client-go` v0.37, `sigs.k8s.io/kind` v0.33.0 as a library, `github.com/google/go-cmp` in tests, Helm 3.22.1 and 4.3.2 for the fixtures. No new dependency.

**Spec:** `projects/rollproof/docs/specs/2026-11-13-rollproof-design.md`. Section numbers are that document's. The amendment this plan builds is, from the repository root, `git diff d022611 21e1112 -- projects/rollproof/docs/specs/2026-11-13-rollproof-design.md` (section 6 "The log stream", section 7 "When the tool fails", section 8 "The command line", section 10 "What a run writes", section 12, section 14 points 26 and 27). Section 8's `limits.timeout` row ("each on its own") is older and unchanged. An executor reads that difference once, and the sections a task names before it starts the task. The items come from the handoff of 2026-11-18, IDs D1 to D16, which each task names.

## Global Constraints

Every task's requirements include these.

- **Linux only.** Module `rollproof`. Apache-2.0. No file under `projects/rollproof/` cites a row of the host repository's decision log or follows its service rules.
- **Paths and commands.** Commands run from `projects/rollproof/` unless a step says "from the repository root". Every command behaves the same in bash and fish: no unquoted glob, no `VAR=value` prefix (write `env VAR=value command`), no `$(…)`. Never set `GOOS` for a `go run` or `go test`.
- **The binary is static.** `env CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=dev" -o bin/rollproof ./cmd/rollproof`.
- **No configuration key, no reason code and no schema version is added.** `result.json` stays at `schema` 1; `stopped_when_asked` becomes `true`, `false` or `null` (section 10). No release carries schema 1 yet.
- **Reason codes,** unchanged: `probe-failures`, `transition-stalled`, `pod-unschedulable`, `command-failed` (fail); `config-rejected`, `runner-unsupported`, `cluster-failed`, `chart-fetch-failed`, `setup-failed`, `install-failed`, `nothing-watched`, `workload-unsupported`, `target-unsupported`, `probe-not-started`, `probe-exited`, `probe-line-invalid`, `steady-not-clean`, `probe-silent`, `no-pod-replaced`, `restart-failed`, `interrupted`, `internal-error` (not verified).
- **Exit codes of `run`** (section 8): 0 pass, 1 fail, 2 not verified. When SIGINT or SIGTERM came during the run, the process ends by that signal after the run has returned, whatever the verdict; a second signal ends it at once. `rollproof probe http` keeps its own handling of SIGTERM (section 6) and is not changed.
- **The probe's stop** (section 6): the pod is deleted with the drain as its grace period; the log is read until the container has exited, for at most the drain and `stopMargin` (5 s). The drain is 10 s for a custom probe and the request timeout plus 5 s for the built-in one.
- **Tests.** Unit tests need no cluster and no network and run with `go test ./...`. A test that needs a container engine carries the build tag `cluster`; a fixture run carries the tag `e2e`. Run those with `-p 1` and with `env CGO_ENABLED=0` before them, because the tool refuses a binary that is not statically linked; on this machine put `env CGO_ENABLED=0 KIND_EXPERIMENTAL_PROVIDER=nerdctl` before them.
- **Commits.** One commit per task, staged by path. A message is a plain sentence that says what changed. It carries no attribution to an AI tool: no `Co-Authored-By` trailer that names one, no "Generated with" line, no session link. Never `--no-verify`, never amend.
- **Nothing leaves the machine.** No push, no pull request and no run on GitHub Actions without the maintainer's word.

## Review Focus

The amendment implies these and names no test for them. Each has its test in the task that owns the code.

1. **The pod reads the container as running for longer than the stop waits, or the stream breaks or stays open.** The run is not verified (a gap), never a pass with lines lost. Task 1, `TestFollowAfterStopTheContainerDoesNotEnd`, `TestFollowAfterStopABrokenStream`, `TestFollowAfterStopTheStopCutsTheLog`.
2. **The probe ignores SIGTERM and is killed at the end of the drain.** The log's end after the kill is still the end: no gap, and `stopped_when_asked` is false. Task 1, `TestFollowAfterStopTakesTheEndWhenTheContainerEnds` covers the follower; the pod's rule is unchanged.
3. **Ctrl-C twice, quickly.** The process ends at the second signal, and the run's own end never comes. Task 3, `TestASecondSignalEndsTheToolAtOnce`.
4. **SIGTERM from a CI system instead of SIGINT.** The same handling, ending by SIGTERM. Task 3, the SIGTERM case of `TestASignalEndsTheToolByIt`.
5. **A signal while the probe starts.** The probe entry gives the lines read, `stopped_when_asked` null and the note, and the reason is `interrupted`. Task 2, `TestASignalDuringTheProbesStart`.

## Alternatives considered

### `internal/probe` `Probe`

Common case: after a signal, `run` writes the probe's entry with the lines the probe wrote, though it never asked the probe to stop.

**A. `Counts` beside `Stop`**
- `Counts() (lines, jsonText int)`

**B. Counts kept by `run` from the events it reads** (expected to lose)
- no new operation; the event reader counts observations

**C. A `Facts()` that gives the Facts so far, stop state included**
- `Facts() Facts`, with `StoppedWhenAsked` as a three-state value

```go
// A
lines, jsonText := s.probe.Counts()

// B
lines := s.reader.observations // misses lines that are faults or JSON text

// C
f := s.probe.Facts() // the probe cannot know that a signal, not it, ended the stop
```

| | A | B | C |
|---|---|---|---|
| Ease of use for the common caller | one call | none, but wrong numbers | one call |
| Interface size | +1 operation | 0 | +1 operation, wider type |
| Generality | any probe that reads a log | only what reaches events | the probe must judge the tool's stop |
| Information hidden | the follower's counters stay inside | the reader must know the line rules | leaks run's reasons into probe |
| Implementation simplicity | reads two atomics | duplicate counting rules | a state machine in two places |
| Efficiency | same | same | same |

Third design: not needed; A removes the caller's work.
Pick: A.
Losers: B, because the follower alone knows which lines were JSON objects with no `ok` field. C, because only `run` knows whether a signal or its own failure cut the stop short.

### `internal/report` `Probe.StoppedWhenAsked`

Common case: a wrapper reads whether the probe stopped when asked, and must not blame a probe that was never asked.

**A. `*bool`, null when not asked, with a note in `Notes`**
- `StoppedWhenAsked *bool` (`json:"stopped_when_asked"`)

**B. `bool`, false with a note** (expected to lose)
- `StoppedWhenAsked bool`

**C. A string `stop`: `stopped`, `not-stopped`, `not-asked`**
- `Stop string` (`json:"stop"`)

```go
// A
if p.StoppedWhenAsked != nil && !*p.StoppedWhenAsked { /* the probe did not stop */ }

// B
if !p.StoppedWhenAsked && len(p.Notes) == 0 { /* guess from the notes */ }

// C
if p.Stop == "not-stopped" { … }
```

| | A | B | C |
|---|---|---|---|
| Ease of use for the common caller | one nil check | must read notes | one comparison |
| Interface size | same field | same field | a new field, the old one gone |
| Generality | three states | two states | three states |
| Information hidden | the reason is in the note | the reason is in the note | the reason is in the code |
| Implementation simplicity | small | smallest | a renamed field in every reader |
| Efficiency | same | same | same |

Third design: not needed.
Pick: A.
Losers: B, because a reader takes false for a probe that ignored SIGTERM (section 14, point 27). C, because the field already exists and section 10 names it.

Design delta: better, because a tool fault and an interrupt are no longer reported as the probe's, and the stop path's waits all have bounds.

### Task 1: The probe's stop path (D1, D7, D8)

**Files:**
- Modify: `internal/probe/follow.go` (`(*follower).run`)
- Modify: `internal/probe/pod.go` (`Start`, `Stop`, `halt`, `lastExitCheck`)
- Test: `internal/probe/follow_test.go`, `internal/probe/pod_test.go`

**Interfaces:**
- Produces: `func (p *Pod) Counts() (lines, jsonText int)`
  How many lines of the probe's log were read so far, and how many of them were
  JSON objects with no ok field. Safe at any moment, from any goroutine, also
  while Start or Stop runs or after either panicked. Zeros before Start.
- Produces: `func (f *follower) waitEnded(ctx context.Context) bool`
  Waits until running says the container has ended, asking every pollEvery.
  True when it has; false when ctx ended first.
- Produces: `func (f *follower) run(ctx context.Context) (ended time.Time)`
  As now, and it returns the moment the last stream ended, read with now when
  that stream returned: never later because of a wait for the pod's status.
- Produces: `func (p *Pod) halt(ctx context.Context, r *probeRun) (Facts, error)`
  The stop of a run whose follower and watcher were started: ends the watcher,
  deletes the pod with the drain as grace, reads the log until it ends or the
  drain and stopMargin pass, closes Events, keeps the Facts and the error.
  Each call to the API waits at most stopMargin.

The `lastCheck` parameter of `halt` goes (D13, D14): `Stop` ends the watcher and runs `lastExitCheck` itself before it calls `halt`; ending the watcher twice is harmless.

- Produces: `type probeStop int` with `notAsked`, `asked`, `cutBySignal`, `stopFailed`

### Task 3: A signal ends the tool by that signal (D15, D16)

**Files:**
- Modify: `cmd/rollproof/main.go` (`main`, `realMain`'s run command)
- Test: `cmd/rollproof/main_test.go`

**Interfaces:**
- Produces: `var runOf = run.Run`
  The run that `rollproof run` starts. A test replaces it.
- Produces: `func runContext() (ctx context.Context, release func())`
  The run's context. It ends at the first SIGINT or SIGTERM, which it keeps for
  endProcess; from then on a second one ends the process at once, by the
  signal's default action. release stops watching for signals.
- Produces: `func endProcess(code int)`
  Ends the process: by the signal that runContext kept, if one came, raised
  again with its default action; otherwise with code. Never returns.

`main` becomes `endProcess(realMain(…))`. `rollproof probe http` keeps `probeContext` unchanged, and `version` and a rejected command line never keep a signal.
