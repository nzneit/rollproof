# Proofs

A proof settles an open point of section 14 of the design before code rests on it. Its program is under `proofs/`, in the module `rollproof-proofs`, and runs from that folder; its record is in this folder. Each program makes one cluster named `rollproof-proof-…`, one at a time, and deletes it, also when the program fails.

Versions in the proofs module: `sigs.k8s.io/kind` v0.33.0; `k8s.io/client-go`, `k8s.io/api` and `k8s.io/apimachinery` v0.37.2; `github.com/google/go-containerregistry` v0.22.1.

## The form of a record

Every record has these headings, in this order:

- `## Question`: the open point, in one or two sentences.
- `## Machine and versions`: the system, the engine and whether it runs without root, Go, kind, the node image, and every other tool the method used, each with its version.
- `## Method`: what the program does, and the exact command that ran it.
- `## Result`: what happened, with the lines of output that show it.
- `## Decision`: what the plan does because of the result.

It ends with a pair of lines for each thing the plan assumed, each line starting at the beginning of its line:

    Plan assumed: "…"
    Holds: yes

`Holds:` is followed by `yes`, `no` or `not measured here`.

## The rule

Part 3 starts when every row that names a task says `yes`. Three exceptions may say `not measured here` instead: point 12 on a machine that is not rootless; point 8 with Docker, which waits for a hosted runner (it ran on one on 2026-11-22 and holds `yes`); and row 11's second assumption, which Task 29's `TestFollowReopensWithoutLossOrRepeat` pins (ruling T9-2). Row 8 with nerdctl says `no`. Their consequences are in the next section.

## What changes

Point 8, nerdctl, holds `no`, and the rule's answer is written here instead of being left implicit. It does not stop Part 3, for these reasons. The design (section 9, "Engines other than Docker") makes Docker the supported engine and says that nerdctl "is expected to work and is not promised". Docker's half of point 8 waits for a hosted runner, which the rule allows; on 2026-11-22 it ran on one and holds `yes`. Every setting that Tasks 20 and 21 take from the record held in every run where kind's `Create` returned. What failed is kind's own 30-second wait for a node's log line inside `Create`, in 5 of 9 first attempts.

Tasks 21, 22, 27 and 29 create clusters through the tool's `cluster.Create` on a machine with nerdctl, so the text of **Task 21** changes. Its Create step 3 tries `provider.Create` again, at most 4 attempts in all. It makes a new attempt only when the error text contains `could not find a log line that matches` and the context has not ended. Before each new attempt it removes the failed attempt with `provider.Delete`, also when the cluster is to be kept, so that only the last attempt's nodes stay. After the last attempt the failure is step 3's, its text unchanged. Task 21 adds a unit test of the retry. No signature, condition or user-visible text changes.

Point 11 holds `not measured here` because its second assumption is not measured; the first and the third hold. No task's text changes for it. Task 29's unit test `TestFollowReopensWithoutLossOrRepeat` covers the counting of lines that share one timestamp. None occurred in the record's runs, even at about 1.3 million lines a second, because containerd stamps each line with its own clock reading in nanoseconds; the record's Decision says why.

Part 3 starts on these decisions. This section waits for the maintainer's review.

## What the proofs leave on the machine

The proofs removed every cluster and container they made. Where a record counted the volumes, the count was the same before and after: `nerdctl volume ls -q` listed 57 in `p01-registry-order`, in `p01b-mirror`, in `p05-helm-cli` and in `p11-log-rotation`, and `p01b-mirror` also records that its named volume existed during each run and was gone after it. `p12-keys` did not count them: its record states only that `nerdctl ps -a` listed no container before and after each run. `p08-kind-library` lists no count either, and records that no volume was created during its runs: kind gives each node an anonymous volume at `/var` and deletes the nodes with `nerdctl rm -f -v`; the proofs' registries also run with `--tmpfs /var/lib/registry` (`proofs/internal/lab/lab.go`), so the engine makes no anonymous volume for the image's `VOLUME`. After the last proof, this command printed no name that starts with `rollproof-proof-`:

    nerdctl ps -a --format "{{.Names}}"

Two things stay that the proofs did not remove: kind's network `kind`, and the node image `kindest/node:v1.37.0`.

## Clock check

Measured on 2026-11-17 by `TestPodOnACluster` (`internal/probe/pod_cluster_test.go`) on rootless nerdctl 2.4.2: the first observation was read 176.461µs after the node's runtime stamped it. The bound is 2 s (`probe.ClockBound`). Measured on 2026-11-22 by the same test on rootful Docker on GitHub's hosted runner (`p24-hosted-runner`): 1.342107ms. An engine in a virtual machine, which can give the nodes a clock of their own, was not measured (section 14, point 21).
